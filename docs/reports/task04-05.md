## Implemented boundary

- `supervisor.New(Config{DataDir, Executable, StopTimeout})` implements the frozen `domain.ProcessSupervisor`. `Start` does not attach the request context to launcher/JVM lifetime. The published PID is the JVM; LauncherPID is diagnostic. Process-running and stopping are distinct from game readiness; this package never promotes readiness.
- `Identity`, `Inspect`, `WithStopped`, `SetAutostart`, `Autostart`, `Shutdown`, `ArmSaveLease`, and `ReleaseSaveLease` provide the consuming service boundary. `Inspect` carries deliberate/forced exit and watchdog failure metadata. Unexpected exits, including exit code zero without deliberate intent, classify as crashed. No native component autonomously retries a JVM; Task 19 owns retry policy.
- Linux uses independent `minecraft@<id>.service` units with `Restart=no`, bounded graceful stop/wait, an unprivileged account, NoNewPrivileges and a private mount namespace exposing only its instance, immutable runtimes and admission lock. There is no manager dependency that would intentionally stop a game on manager restart. This intended behavior still needs real unit evidence.
- Linux control is bound to **exactly** `/var/lib/minecraft-ui` and `/usr/local/bin/minecraft-ui`. Other configured roots/executables fail closed before privileged control. Root-owned, nonwritable binary/helper/template paths and ancestors are checked. Loaded FragmentPath, absence of drop-ins, exact argv/data-root/instance, User/Group, Restart and KillMode must match. Unrecognized `systemctl show` formatting fails closed. Custom deployment roots/overrides require a separately reviewed contract.
- The fixed root-owned `unitctl` helper allows only start/stop/enable/disable, exact argument counts and validated instance IDs. It has no upgrade, shell-command or arbitrary unit verbs. Games cannot use the manager's sudo grant because their unit sets NoNewPrivileges.
- Windows starts a separate launcher whose parent stdin EOF triggers graceful stop, bounded force if necessary, and Wait. JVM creation is suspended until kill-on-close job containment succeeds, then its primary thread resumes. A failed containment/resume path fails closed. Shutdown closes all parent pipes first and waits concurrently. In-flight Start admission closes before shutdown snapshots children.
- Linux identity binds boot ID, `/proc` start ticks, image and cwd. Windows binds boot GUID, creation FILETIME and image; remote cwd lacks a stable documented Win32 API, so private launcher metadata and authenticated control bind it. Missing/unreadable identity fails closed. A conclusively different boot/start token proves the original exited and never signals a reused foreign PID.
- Admission locks live at `dataDir/locks/<id>.lock`, outside deletable/renamed instance trees. They remain after deletion to retain lock inode identity on ID reuse. `WithStopped` holds this OS lock plus the same manager lifecycle exclusion used by Start/Stop/autostart changes. The launcher holds the lock for its complete lifetime. Guard acquisition creates no ghost instance directory.
- `dataDir/manager.lock` is separate, private, never removed, and acquired before database opening/migrations/job recovery. A rejected second manager cannot modify the first manager's running jobs. Private lock files reject symlinks.

## Launcher, console and save-lease handoff

`launcher.Run(ctx, Config{DataDir, InstanceID, StopOnStdinEOF, StopTimeout}, stdin)` owns JVM stdin, Wait, bounded logs and independent lease recovery. `runLaunch` is centrally dispatched before normal serve/version arity checks. State files are under `instances/<id>/state`; raw stdout/stderr are `instances/<id>/logs/console.log`, `.1`, `.2`, each bounded to 4 MiB for a 12 MiB retained stream. Task 10 must reopen on rotation and implement authorized replay, redaction, version-aware parsing and telemetry-gap disclosure.

Control binds only IPv4 loopback, uses a fresh random 256-bit bearer secret in private control.json, disables proxies/redirects on the client, limits bodies/timeouts and checks the complete identity locally and remotely. Tokens and private environment overrides are never exposed in API DTOs or logs. A successful stdin write is **delivery only**, never Minecraft acknowledgement or completion. Task 10/13 must independently establish acknowledged flush fences.

`ArmSaveLease(ctx, identity, leaseID, expiresAt)` installs a monotonic deadline capped at five minutes and emits save-off under the same serialization. Existing leases cannot be extended or replaced. The independent launcher attempts save-on on expiry or release; failed delivery is retried at most 30 times at one-second watchdog ticks while the process lives and remains visible in status/exit metadata. Wrong/expired releases fail closed; the backup coordinator must reconcile outstanding leases and always attempt save-on on its failure paths. This transport is not the complete Task 13 backup lease service.

Generic commands reject save-off, lifecycle verbs, leading slash/case/namespace variants, and indirect execute/function/schedule/return/debug-function paths. This is a **trusted internal transport fence**, not a public command safety policy. Unknown mod/plugin commands can have arbitrary behavior; Task 10 must provide its role/version allowlist. Stop and lease operations use their dedicated authenticated routes. Operator stop is not acknowledged until durable intent records successfully; shutdown/EOF still attempts graceful cleanup if persistence fails. Missing final exit metadata, forced termination and recorded recovery failures are surfaced as errors.

## Central composition implemented with integrator authorization

- Shared instance IDs now reject reserved Windows device names, with domain regressions.
- Main acquires the manager lock before SQLite; composes jobs.WithIdle -> native.WithStopped -> instance mutation; starts jobs; reconciles durable instance state; then calls native Autostart(nil) and exposes authenticated instance routes alongside auth/jobs.
- Deferred reconciliation for live/busy/unverifiable instances preserves onboarding. Hard ownership/journal failures block mutations while read/create remain available.
- HTTP drains for up to ten seconds; jobs Stop and native Shutdown then run concurrently under an independent 110-second context. The database closes after both calls; the manager lock releases last.
- SCM dispatch/StopPending handling is implemented, but unqualified. Actual Windows automatic starts are deliberately pending a provider-validated installation/config/runtime resolver. Startup currently reconciles/waits old JVMs only. Stale launch.json alone is insufficient to start automatically.
- Before real provider job handlers integrate, jobs need a paused startup/resume boundary so dispatch cannot race Windows native or instance reconciliation. Root is coordinating that prerequisite. Future job-owned canonical materialization also needs a reviewed current-job guard contract; calling Materialize recursively inside WithStopped/WithIdle would deadlock or conflict.
