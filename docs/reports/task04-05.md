## Implemented boundary

- `supervisor.New(Config{DataDir, Executable, StopTimeout})` implements the frozen `domain.ProcessSupervisor`. `Start` does not attach the request context to launcher/JVM lifetime. The published PID is the JVM; LauncherPID is diagnostic. Process-running and stopping are distinct from game readiness; this package never promotes readiness.
- `Identity`, `Inspect`, `WithStopped`, `SetAutostart`, `Autostart`, `Shutdown`, `ArmSaveLease`, and `ReleaseSaveLease` provide the consuming service boundary. `Inspect` carries deliberate/forced exit and watchdog failure metadata. Unexpected exits, including exit code zero without deliberate intent, classify as crashed. No native component autonomously retries a JVM; Task 19 owns retry policy.
- Linux uses independent `minecraft@<id>.service` units with `Restart=no`, bounded graceful stop/wait, an unprivileged account, NoNewPrivileges and a private mount namespace exposing only its instance, immutable runtimes and admission lock. There is no manager dependency that would intentionally stop a game on manager restart. This intended behavior still needs real unit evidence.
- Linux control is bound to **exactly** `/var/lib/minecraft-ui` and `/usr/local/bin/minecraft-ui`. Other configured roots/executables fail closed before privileged control. Root-owned, nonwritable binary/helper/template paths and ancestors are checked. Loaded FragmentPath, absence of drop-ins, exact argv/data-root/instance, User/Group, Restart and KillMode must match. Unrecognized `systemctl show` formatting fails closed. Custom deployment roots/overrides require a separately reviewed contract.
- The fixed root-owned `unitctl` helper allows only start/stop/enable/disable plus scoped read-only inspect, exact argument counts and validated instance IDs. It has no upgrade, shell-command or arbitrary unit verbs. Games cannot use the manager's sudo grant because their unit sets NoNewPrivileges.
- Windows starts a separate launcher whose parent stdin EOF triggers graceful stop, bounded force if necessary, and Wait. JVM creation is suspended until kill-on-close job containment succeeds, then its primary thread resumes. A failed containment/resume path fails closed. Shutdown closes all parent pipes first and waits concurrently. In-flight Start admission closes before shutdown snapshots children.
- Linux identity binds boot ID, `/proc` start ticks, image and cwd. Windows binds boot GUID, creation FILETIME and image; remote cwd lacks a stable documented Win32 API, so private launcher metadata and authenticated control bind it. Missing/unreadable identity fails closed. A conclusively different boot/start token proves the original exited and never signals a reused foreign PID.
- Admission locks live at `dataDir/locks/<id>.lock`, outside deletable/renamed instance trees. They remain after deletion to retain lock inode identity on ID reuse. `WithStopped` holds this OS lock plus the same manager lifecycle exclusion used by Start/Stop/autostart changes. The launcher holds the lock for its complete lifetime. Guard acquisition creates no ghost instance directory.
- `dataDir/manager.lock` is separate, private, never removed, and acquired before database opening/migrations/job recovery. A rejected second manager cannot modify the first manager's running jobs. Private lock files reject symlinks.

## Launcher, console and save-lease handoff

`launcher.Run(ctx, Config{DataDir, InstanceID, StopOnStdinEOF, StopTimeout}, stdin)` owns JVM stdin, Wait, bounded logs and independent lease recovery. `runLaunch` is centrally dispatched before normal serve/version arity checks. State files are under `instances/<id>/state`; raw stdout/stderr are `instances/<id>/logs/console.log`, `.1`, `.2`, each bounded to 4 MiB for a 12 MiB retained stream. Task 10 must reopen on rotation and implement authorized replay, redaction, version-aware parsing and telemetry-gap disclosure.

Control binds only IPv4 loopback, uses a fresh random 256-bit bearer secret in private control.json, disables proxies/redirects on the client, limits bodies/timeouts and checks the complete identity locally and remotely. Tokens and private environment overrides are never exposed in API DTOs or logs. A successful stdin write is **delivery only**, never Minecraft acknowledgement or completion. Task 10/13 must independently establish acknowledged flush fences.

`ArmSaveLease(ctx, identity, leaseID, expiresAt)` installs a monotonic deadline capped at five minutes and emits save-off under the same serialization. Existing leases cannot be extended or replaced. The independent launcher attempts save-on on expiry or release; failed delivery is retried at most 30 times at one-second watchdog ticks while the process lives and remains visible in status/exit metadata. Wrong/expired releases fail closed; the backup coordinator must reconcile outstanding leases and always attempt save-on on its failure paths. This transport is not the complete Task 13 backup lease service.

Generic commands reject save-off, lifecycle verbs, leading slash/case/namespace variants, and indirect execute/function/schedule/return/debug-function paths. This is a **trusted internal transport fence**, not a public command safety policy. Unknown mod/plugin commands can have arbitrary behavior; Task 10 must provide its role/version allowlist. Stop and lease operations use their dedicated authenticated routes. Operator stop is not acknowledged until durable intent records successfully; shutdown/EOF still attempts graceful cleanup if persistence fails. Missing final exit metadata, forced termination and recorded recovery failures are surfaced as errors.

## Central composition implemented with integrator authorization

- Main acquires the manager lock before SQLite; composes jobs.WithIdle -> native.WithStopped -> instance mutation; starts jobs; reconciles durable instance state; then calls native Autostart(nil) and exposes authenticated instance routes alongside auth/jobs.

Future job-owned canonical materialization also needs a reviewed current-job guard contract; calling Materialize recursively inside WithStopped/WithIdle would deadlock or conflict.

## Review round 1 fixes (base eb9cfa1)

Status remains **DONE_WITH_CONCERNS**. The five Important findings have code and
scoped regression coverage; actual native acceptance and isolation qualification
remain pending. No units were installed, no real Minecraft server/EULA action was
performed, and this worker did not stage/commit or update the ledger.

1. **Linux process/mount boundary:** game units now require PrivateUsers=yes,
   minimal identity mappings, a root-created namespace, zero effective
   capabilities and NoNewPrivileges. The data root is read-only tmpfs; the
   instance parent, runtimes, server/.manager and activation are pinned read-only,
   with pinned writable server/logs/state/lock children. Parent pinning prevents
   rename/unlink from replacing protected activation or artifact trees. Production
   launch checks actual namespace/map/mount state before exec. Mount isolation
   alone was insufficient against same-account /proc access.

   A root-owned `unitctl inspect ID` / hidden `native-inspect --instance ID`
   bridge derives the loaded unit's MainPID, cgroup, invocation and unique direct
   JVM child. It checks a distinct root-created user namespace, actual pinned
   mounts, parent/cgroup membership, stable unit identity and live pidfds before
   returning bounded boot/start/image/cwd identity only. No arbitrary PID/path/
   command/environment input, namespace entry, signal or manager CAP_SYS_PTRACE
   is permitted. Manager production reattachment always requires this proof,
   even if direct /proc reads succeed: changing the loaded template cannot make
   a pre-hardening running process appear isolated. Such a game is unknown /
   repair-needed and is left untouched pending planned restart. Unified cgroups,
   pidfds and namespace-owner inspection are host prerequisites that fail closed.
   Metrics consumers must retain strict identity checks and disclose unavailable
   fields; this bridge is not an arbitrary metrics/proc API. PrivateUsers retains
   the host UID and is a ptrace/process-capability boundary, not distinct-UID
   isolation: ordinary same-UID signals remain a denial-of-service risk. This
   report does not claim a complete hostile-game-code sandbox.

2. **Accepted stop / done race:** durable operator acceptance and final exit
   classification now share session.mu. finalizeExit carries the accepted reason
   even when JVM Wait wins before the queued stop is consumed. The regression
   deliberately leaves that queue unconsumed and verifies deliberate/operator.

3. **Dead JVM completion:** Stop routes even a conclusively exited JVM through a
   bounded wait for launcher admission-lock release and final inspection.
   Missing final metadata, forced exit, recovery error or non-deliberate/nonzero
   completion is an error; repeated Stop cannot turn a forced failure into nil.
   Tests hold the launcher lock after proven original exit and preserve each
   final failure. The unrelated live reused PID is never signalled.

4. **Windows EOF recovery reporting:** final persisted watchdog/recovery failures
   now produce a nonzero launcher return even after JVM exit zero. Windows waits
   on that launcher result. A real helper-process EOF test blocks durable stop
   persistence, lets the JVM stop cleanly, then verifies final error metadata and
   nonnil Run result. This is deterministic process evidence, not native Windows
   SCM qualification.

5. **Verified boot/activation:** Seal(ctx,dataDir,id,spec) verifies offline before
   atomic WriteSpec; callers must already hold stopped mutation exclusion and it
   acquires no lock. Supervisor.Start uses Seal and invalid specifications leave
   prior activation untouched. Run performs the same verification before spawn,
   plus Linux self-isolation checks. runtime.Manager.Get rehashes immutable
   runtime inventory/provenance; ID/checksum/image/host must match exactly.
   server.VerifyLaunch dispatches Vanilla/Paper or loader verification. JAR
   receipts bind exact selection/artifact/runtime requirements and rehash the
   immutable JAR; loader verification is owned by Task08 and validates full
   inventory, runtime-bound receipt and reconstructed argv/argfiles. Only absent
   memory prefix or canonical Xms=min(512,Xmx), Xmx=256..1048576 MiB is accepted;
   the lifecycle coordinator must bind that value to current DB MemoryMiB while
   sealing. No arbitrary JVM flags are approved. All nonempty LaunchSpec.Env are
   rejected until a coordinated typed environment policy exists, and inherited
   Java/native loading variables are stripped. Arbitrary helper executables have
   only an unexported package-test seam; production constructors/CLI have no bypass.

### Current Windows security limitation

Windows JVMs use the manager's account. Job Objects contain process lifetime,
not credentials or filesystem access. No restricted token or per-instance ACL
boundary has been implemented or qualified; game/mod/plugin code can read/write
manager.db and other instances wherever that account has permission. A private
data tree only excludes other accounts. Do not claim cross-instance/manager file
isolation on Windows. This is an explicit architecture/acceptance gap; root was
notified and this fix pass did not silently broaden into Windows token/ACL design.
