# Product parity audit against public Valheim Server UI

2026-10-17. Minecraft baseline `c13fb51`; read-only Valheim reference `dabec19585e3f401eceb127840c71542fa84dac1` (public main / v1.21.3, verified by integrator). This is a source and existing acceptance-evidence audit, not a new browser run or broad code review. No application, reference, dependency, host, or ledger change is part of this report.

**The Minecraft product is not at user-facing parity with the public reference.** Reviewed implementations and successful native package/build CI establish a substantial foundation. They do not establish an equally complete daily operating experience or the first usable game server. Several visible reference capabilities are absent, independently of the pending real game/platform qualification.

## Approved differences and boundaries

Minecraft keeps Java-only server flavors, managed per-instance Temurin, strict version compatibility and pinned updates, native control/provenance, online backup save leases, stopped confirmed safety restore, and saved-world dimensions/height slicing. Valheim game mechanics, SteamCMD, BepInEx, agent gameplay helpers, texture/cartography layers and platform IDs are not literal requirements. Bedrock, Docker, remote hosts/backups, existing-server imports, world uploads, mandatory addons and client-pack exports remain excluded. The current world discovery/download UI is within that boundary; the reference's world upload/switch/reset controls must not be copied as an assumed requirement.

Capture Linux first, then native Windows; record actual blockers and fix them before broadening the version/loader matrix. Requires explicit EULA/test-host authority where absent. 2. **Daily operating shell/dashboard:** persistent instance context and feature switching, truthful live cards/summary, resource trends, explicit theme control and exact-job access. 3. **Console and player operations:** persisted-log browsing/download/filter/follow plus safe highlighting; known-player action/prefill retaining identity provenance. Demonstrate with actual captured logs/player records, not exclusively fixtures.
4. **Complete content workflow:** add discoverable result/release paging, decide bounded dependency-plan UX and resolve documented compatibility blockers through reviewed installer evidence; demonstrate official addon and pack install/config/lifecycle on qualified servers. ## Frozen dashboard contract assessment

The current generated contracts are sufficient for a truthful per-instance dashboard without backend additions:

- `GET /api/v1/instances` returns `InstanceDetail[]`: saved identity/version/port/memory, provisioning and EULA/settings projections. It does **not** contain runtime/player/resource state.
- `GET /api/v1/instances/{instanceId}/lifecycle` returns `LifecycleState`: `installed`, exact selection, `process`, `process_running`, `readiness`, `autostart_desired`, nullable `autostart_applied`, optional `autostart_error`. Existing LifecyclePanel polls it every five seconds. Preserve process versus readiness and unknown native policy separately.
- `GET /api/v1/instances/{instanceId}/players` returns `PlayerSnapshotResponse.snapshot`: `known`, `complete`, `count`, `players`, `gap`, `reason`, `observed_at`, `generation`. Show zero only when the current observation actually establishes zero; incomplete/unknown/stale observations do not establish an exact fleet total.
- `GET /api/v1/instances/{instanceId}/metrics?from=<RFC3339>&to=<RFC3339>&resolution=raw|hourly` returns `MetricsPage.points`: nullable `cpu_percent`, `resident_bytes`, `private_bytes`, `disk_bytes`, `players`, plus timestamp, `counts`, `expected`, `gap` and per-field sources. Suitable for recent cards and trends. Nulls/gaps must stay visible and break chart lines; old values must retain their timestamp/stale state. JVM CPU is percent of one logical CPU, not whole-host utilization.

See `docs/openapi.yaml`, generated `web/src/api/schema.d.ts`, `internal/api/lifecycle_handlers.go`, `internal/api/metrics_handlers.go`, and existing `LifecyclePanel.tsx`, `PlayersPage.tsx`, `MetricsPanel.tsx` consumers. No host-wide CPU/memory/free-disk or aggregate health endpoint was found in the inspected shipping schema: instance JVM counters and logical instance bytes cannot safely impersonate Valheim's host strip. Root must own any such new contract. Existing per-instance reads require bounded/concurrent polling with cancellation, stale handling and no fabricated healthy fallback; a fleet aggregation endpoint is an optional scalability decision, not a prerequisite for honest current-contract cards.
