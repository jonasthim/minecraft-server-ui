# Task 16 frozen content consumer contract

`internal/content/types.go` defines `Tuple`, `Installed`, `OwnedFile`, `Manifest`, `Mutation`, `Preview`, `Upload`, and `ConfigText`. `ConfigListing` in config.go includes `files`, `truncated`, `unsupported`.

Service construction: `New(Config{DB, Paths, Instances, Queue, Catalog, Recovery}) (*Service,error)`; call `Register()` before queue start. Run `Reconcile(ctx)` after `jobs.StartPaused` and before native starts or `jobs.Resume`. `Recovery` implements `WithStoppedForRecovery(ctx,id,fn)`.

Consumers use `Snapshot(ctx,instanceID) (Manifest,error)` with `Revision`, exact `Tuple`, installed `Items`, and `AutomaticBlockers`. Unknown trials, outstanding journals, unresolved/manual previews block automatic updates. Source and file verification are distinct from tested game support.

Mutations use `Preview(ctx,id,Mutation,actor)`, `Enqueue(ctx,id,previewID,actor)`. API accepts publisher identifiers or an owned upload ID, never an artifact path or asserted digest. Administrator `StageUpload(ctx,id,filename,reader,actor)` is bounded and inert. Unknown trials apply only to the recorded tuple; they retain unknown status. Required dependencies are explicitly blocked until installed; no automatic transitive download graph is followed. Direct metadata dependency list is bounded at 128, so recursive depth/cycles are not entered by this service. `Discard` releases unused actor staging after removing a preview.

Limits: 2 GiB/artifact, 256 stages and 8 GiB/instance, 16 GiB global staging, 2048 installed items, 32 previews/instance, 24-hour preview/upload TTL, two global uploads. The service conservatively serializes content stage quota admission and publication with one mutex. Other feature queues retain their own admission. Journal and preview stage references prevent expiry. Private files live under instance `state/content/<random>.blob`; SQLite contains metadata only.

Config policy: `config/**`, `defaultconfigs/**`, `plugins/<portable-addon>/**`; text extensions toml/json/json5/yaml/yml/properties/cfg/conf/txt. Eight path components, 1 MiB/file, 1000 visited directory entries/list. Hidden, reserved and manager/control/runtime/world locations, links, hardlinks, binary/NUL/non-UTF8 data are rejected. Viewer sees file metadata only; `ConfigRead` and config mutation require operator. Whole-file text replacement preserves submitted keys/comments. Config writes are queued and stopped-only; no hot reload or implicit lifecycle changes.

Task 17/18 transaction composition is not granted through `Enqueue`: it would nest job/native admission. A future coordinator needs a scoped content participant prepared inside its existing admitted stopped session: validate manifest revision/tuple and immutable staged preimages, append owned operations to a coordinator journal, contribute manifest SQL to its transaction, finalize/reconcile under the same capability. The coordinator must own the single journal/commit and hold all participant capabilities until cleanup. Until that interface is reviewed, Snapshot/preview are consumer interfaces and independent applies cannot be presented as a pack/update transaction.

Readiness addition approved during integration review: `Service.CheckReady(ctx,id)` gates ordinary lifecycle/config/content work on both SQL journals and the independent exact instance/preview `state/content-transaction.json` marker. `Reconcile` uses paused stopped admission, audits orphan/malformed markers and clears a blocker only after durable verified committed/rolled-back outcome. Delegated launcher checker is reached from `CheckActivationReady` for native Start and independent Run. Root must compose this readiness with existing backup/config checks and must not apply it recursively to stopped recovery.

Review fix round 1: install/update/enable validate the complete proposed enabled manifest through one indexed compatibility checker, rechecked immediately before apply. It validates persisted publisher requirements/incompatibilities, descriptor requirements/conflicts in both directions, duplicate descriptor/publisher identities and retained exact trial tuples. A trial never waives a known contradiction. Disabled items are excluded from the active set; their recorded requirements become mandatory when enabled.

Preview admission ownership is now derived from durable jobs, rather than a standalone queued flag. Unreleased migration 00010 adds `content_previews.job_id` and a content-specific unique live-job index on `(instance_id, payload.preview_id)` for queued/running content jobs. The durable queue insert acquires uniqueness before the preview queued/binding update. Interrupted binding is repaired from the job's immutable private reference during worker/startup/next admission checks. Retry/discard require no live job and no recovery journal; failures before journal creation and queued cancellations can be retried or discarded once their durable job is terminal. Handler return alone never releases ownership. TTL cleanup retains live-job preview/stage references. Discard reports a conflict or missing/foreign preview explicitly rather than claiming a zero-row deletion succeeded. No public API/schema change.

Collision checking reads at most 64 directory entries per batch, checks context between batches and refuses directories above the same 4096-entry verification bound used by Snapshot.
