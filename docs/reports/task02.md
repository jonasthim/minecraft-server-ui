# Task 02 — Identity

Implemented local first-admin setup, account CRUD, Argon2id password validation, bounded login lockouts, hashed revocable sessions, hardened cookies, session-bound CSRF, global role enforcement, personal tokens with enforced read/operate/admin scope caps, one OIDC provider with verified authorization-code/PKCE flow, persistent identities and settings, and redacted audit events.

UI exports `AuthProvider`, `AuthGate`, `AccountPage`, `UsersPage`, `OIDCSettingsPage`, and `AuditPage`. All mutations call real APIs. There are no seeded/default credentials or frontend-only permission decisions. `web/src/api/client.ts` automatically obtains the session CSRF token. Identity routes are available through `api.MountAuth` or `Service.MountRoutes` on a shared `/api/v1` router after installing Authenticate and CSRF. Feature groups must still apply RequireRole.

Selective reuse: copied and adapted reviewed Valheim authentication primitives, SQLite user/session/token repositories, role mapping and full signed fake-provider OIDC tests. Removed Valheim configuration and game-specific settings coupling. Added atomic permanent bootstrap claim, database last-admin triggers, signed/replay-protected OIDC state, disabled-account session checks, role-capped token scopes, bearer fallback protection, bounded Argon2 parsing, and complete browser forms.

Verification: 49 authentication tests pass, including 44 adapted source tests and five new HTTP/security integration tests. Full signed local OIDC provider login tests exercise discovery, signed tokens, group roles, user-info claims, account linking, and sessions. New tests cover missing CSRF, foreign Origin, logout revocation, bearer/cookie precedence, scope caps, browser-only identity management, token/audit redaction, independent-service bootstrap races, SQL last-admin protection, and malformed/unsafe Argon2 parameters. `go test ./internal/auth ./internal/db ./internal/api ./internal/audit` passed. `npm run build` passed with all identity components.

Limits: real external IdP and browser end-to-end verification remain integration work; no claim is made that a particular external provider has been tested. Login lockouts and the OIDC signing key are per manager process; a restart invalidates pending OIDC flows. OIDC settings and token scopes have a separate OpenAPI fragment for final foundation merge. Session expiry and role/disabled state are rechecked on every request. No optional second-factor or email delivery workflow is included in the approved scope.
