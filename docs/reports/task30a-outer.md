## Interfaces and ownership

New `release/outer` exposes `Produce(context.Context, Config) error`. Config has
`Repository`, exact preparer `Version`, `LinuxPreparer`, `WindowsPreparer`,
`TrustFile`, absolute new `Output`, and `Development`. New `release/cmd/outer`
provides the corresponding CLI:

```sh
go run ./release/cmd/outer \
  --repository jonasthim/minecraft-server-ui --version v0.0.1 \
  --linux-preparer bin/minecraft-ui-bootstrap-linux-amd64 \
  --windows-preparer bin/minecraft-ui-bootstrap-windows-amd64.exe \
  --trust-file /absolute/independently-reviewed-public-trust.json \
  --out /absolute/private-parent/new-outer-artifacts
```

Use `--development` only for development entry scripts and fixture trust. No
private signing key, credential, production key generation or signing input is
accepted. Receipts are adjacent `<binary>.version.json` with command
`minecraft-ui-bootstrap`, exact version, native OS, amd64, schema zero and exact
binary SHA256. Receipts are unsigned provenance; they do not prove native
execution. Actual native command logs remain required.

The only shared addition is `candidate.SnapshotNativeInput`, a thin exported
adapter over the existing bounded regular-source snapshot, Go build information,
ELF/PE identity and strict receipt verifier. It accepts only the existing manager
(positive schema), updater (schema zero), and new preparer (schema zero), on
Linux/Windows amd64. Its destination must be absent inside a private
caller-controlled directory, with trusted ancestry for the entire operation.
Existing producer code, format1 metadata, archive allowlists and outputs are
unchanged.

Producer output contains exactly:

- `minecraft-ui-bootstrap-linux-amd64`
- `minecraft-ui-bootstrap-windows-amd64.exe`
- `minecraft-ui-prepare.sh`
- `minecraft-ui-prepare.ps1`
- `bootstrap-entry.json`

The entry document records format 1, repository, preparer version, public trust
file SHA256, development boolean and exact four asset sizes/hashes. There are no
timestamps or source paths in generated bytes. The public trust file is parsed
through `candidate.ParsePublicTrust` with its 16 KiB bound and snapshotted into
the scripts. Both binary inputs are privately snapshotted before validation and
publication. Binary and Bash output modes are 0755; JSON and PowerShell are 0644
under a new private 0700 directory. Existing files/directories/dangling symlinks
are refused. Publication is an exclusive new directory, not an atomic directory
transaction; consume output only after successful process exit. Errors remove
only owned output with its retained identity and private temporary snapshots.
The caller must supply a trusted private output parent; this producer is not a
privilege boundary.

## Entry behavior and first trust

```sh
bash minecraft-ui-prepare.sh --version latest --output /absolute/new-inputs
# Development scripts additionally require --allow-development.
```

```powershell
.\minecraft-ui-prepare.ps1 -Version latest -Output C:\private\new-inputs
# Development scripts additionally require -AllowDevelopment.
```

Manager selection defaults to `latest`, or accepts an explicit stable version.
The executable download URL always contains the exact separately supplied
preparer release, never the manager selection or mutable latest executable URL.
Both scripts embed the reviewed public trust and exact native preparer size/hash.
Only verified preparer bytes may reach the final native invocation. Its arguments
use Bash arrays or PowerShell array splatting, and the preparer only validates and
extracts authenticated inputs. Neither entry script invokes bundle installers or
changes services, accounts, firewall, trust configuration or game state.

The initial trust anchor is the independently reviewed release-specific script.
Downloading a script, verifier and keys together from an untrusted location does
not establish publisher identity. `bootstrap-entry.json` is public provenance,
not a signature or a replacement for that independent review. No production
publisher identity or public release is established in this packet.

Linux requires x64 Debian/Ubuntu and already installed curl, sha256sum and basic
coreutils. It never installs prerequisites. It disables curl configuration and
proxies, uses fixed HTTPS URLs, limits transfers/time/redirects, bounds staged body
bytes even without Content-Length, and accepts redirects only to GitHub's exact
HTTPS release-assets host. Raw network errors and signed query text are private.
A fresh umask-077 temporary directory under OS `/tmp` is cleaned on success,
failure and handled cancellation. Verified native stdout is bounded to 32 KiB.

Windows requires PowerShell 5.1+ and a native x64 process on x64 Windows, local
clean drive paths and built-in TLS1.2/HTTP/SHA256. A small embedded Add-Type Win32
adapter supplies atomic protected file creation with an explicit owner,
handle-bound file IDs/security checks, and deletion through the checked handle.
There is no post-create ACL repair or external dependency. Proxy, credentials
and automatic redirects are disabled. Downloads stream with byte and time
limits; redirects require exact HTTPS host, no credentials/fragment and port 443.

Scratch ancestry/reparse status and owner/DACL are rechecked before execution.
Each of the four fixed files is created with the explicit owner and protected
DACL in CREATE_NEW itself, and its volume/file ID is recorded. The directory
handle forbids deletion through preparation. Trust and verified executable
handles forbid write/delete sharing through invocation. Precreated result/error
read handles permit PowerShell writers while preventing replacement.
Non-elevated files and directory permit only current identity, Administrators
and SYSTEM. Elevated files and directory have owner Administrators and DACL only
Administrators/SYSTEM; same-user implicit owner rights are not relied on. The
script never elevates. Before Add-Type runs, pure .NET APIs create the private
directory and check its ACL. Process TEMP/TMP point at that directory only during
compilation, and exact previous values (including absence) are restored in finally.
The built-in compiler's internal file operations still need native observation;
no compiler exploit or native safety qualification is inferred from source.

Cleanup handles only fixed names successfully created by this process. Each
DELETE handle must match the recorded file ID, owner and complete protected DACL
before disposition. Unknown children are never enumerated for deletion.
Replacements, reparse points, changed ownership/security and a nonempty directory
cause authored cleanup refusal, nonzero exit and no success JSON. Final directory
deletion checks its original ID/security on the DELETE handle and requires an
empty directory. If compilation fails before binding is available, the private
directory may be preserved with a cleanup refusal. Already prepared output is
preserved. Administrators/SYSTEM remain trusted principals. Future privileged
lifecycle handoff must independently verify the prepared output at its boundary.

## Verification evidence

Executed locally:

```sh
go test -race -count=1 ./release/outer ./release/cmd/outer
go test -race -count=1 ./release/candidate -run TestNativeSnapshot
go vet ./release/outer ./release/cmd/outer ./release/candidate
```

Producer tests build tiny real Go ELF/PE fixtures without executing them, bind
their exact receipts, compare every output byte across independent runs, and
check provenance sizes/hashes and both exact binary copies. Negative controls
cover command/platform/version/hash/schema mismatch, unknown/duplicate/missing
receipt fields, wrong executable identity/platform, unsafe source symlinks,
existing file/directory/dangling output preservation, cancellation, bad public
trust identity/bounds/duplicate JSON and unstable/overflowing preparer versions.
The focused adapter test rejects unknown commands/platforms and invalid schema
contracts before I/O.

Bash behavior tests execute the rendered script using trusted test-only seams:
fake curl, a Debian os-release fixture and a fake final runner. The development
host is CachyOS; this is source behavior evidence, not native Debian qualification.
Fixture preparer bytes never execute. The shipping size/hash checks remain in
the executed code. Same-size tamper, oversized/truncated payloads, failed download,
wrong-host redirect and missing development consent cannot reach the runner.
Allowed signed GitHub redirects remain private. Malicious manager versions are
refused, malicious-looking output text remains one literal argument, and only
owned scratch is cleaned while sibling files remain intact. A temporary removal
of the SHA256 guard made the tampered-preparer regression fail by reaching the
runner; the original guard was restored and race tests passed afterward.

`release/outer/windows_behavior_test.ps1` is supplied for the hosted Windows gate:

```powershell
.\release\outer\windows_behavior_test.ps1 `
  -EntryScript C:\private\outer\minecraft-ui-prepare.ps1 `
  -PayloadPath C:\private\outer\minecraft-ui-bootstrap-windows-amd64.exe
# Add -Development when testing development-generated entry scripts.
```

That harness parses the actual rendered script, executes its actual pure redirect
policy with allowed and hostile URLs, and uses explicit test-only AST downloader
and final-runner replacements to exercise ACL creation/checks, hashing, exact
size, literal arguments, development refusal, scrubbed failures and cleanup.
An observer wraps the shipping file-creation function and independently checks
every actual fixed child immediately after creation: exact owner SID, protected
DACL, exactly the required principals and explicit full-control rules, without
inherited/extra rights. Success requires observations of all four files. Native
cases also preserve an unknown child, refuse cleanup after an elevated child
owner change, and assert that the retained executable cannot be renamed through
the runner phase. The successful test logs the public names/owner/allowed SIDs.
It launches no preparer binary and needs no network. PowerShell is unavailable
on this development host, so this harness and generated PowerShell parsing have
not been executed locally. Hosted native execution must be reviewed before any
Windows behavior claim. Actual pinned/latest public acquisition, native build
receipts, installed lifecycle and stable qualification/publication remain with
the integrator. No staging, commits, services, accounts, firewall changes,
downloaded executable execution or game activity occurred locally.

The previous elevated child-default-owner issue is corrected in source by atomic
explicit ownership/protected DACL creation. The embedded C# source compiled in
C#5 language mode against existing local .NET reference assemblies using the
installed Roslyn compiler, without invoking Windows APIs or an acquired binary.
PowerShell 5.1/7 parsing, API behavior, actual owner/DACL observations, compiler
scratch behavior, output-file redirection sharing and cleanup disposition still
require the hosted native gate. No Windows safety claim is inferred from C# or
Go source compilation.
